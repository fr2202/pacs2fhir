Origem

Como nasceu o projeto

Tudo começou com um conjunto de dados. Quando o CHULN — Centro Hospitalar Universitário de Lisboa Norte — disponibilizou 10.001 relatórios radiológicos anonimizados no âmbito da agenda do projeto BLOCKCHAIN.PT, surgiu a questão central: como transformar estes dados clínicos não estruturados, exportados em JSON aninhado com narrativas em RTF, no padrão universal HL7 FHIR R4?

SETEMBRO 2024
Acesso aos dados CHULN via BLOCKCHAIN.PT
Recebemos 10.001 relatórios de TC anonimizados do Centro Hospitalar Universitário de Lisboa Norte, em formato JSON com narrativas RTF incorporadas — o ponto de partida de tudo.
OUT – DEZ 2024
Exploração dos dados e análise da norma HL7 FHIR
Mapeamento da estrutura dos dados: campos em falta (exam_date, episode), qualidade da coleção, definição das perguntas de investigação (SLR) e escolha da norma FHIR R4 como destino.
JAN – MAR 2025
Pipeline PACS→FHIR + integração Projeto EI 2024/2025
Desenvolvimento do pipeline multi-agente em Python. Integração com o projeto de Engenharia Informática (aplicação web com API Flask + MongoDB). Throughput de 1.173 ficheiros/segundo, zero erros.
JULHO 2025
Primeiro artigo submetido — HCIST 2025
"PACS-to-FHIR Transformation and Clinical Text: a Case Study with Computed Tomography" submetido e aceite na conferência HCIST. Publicado no Procedia Computer Science (ScienceDirect).
NOV 2025
Apresentação na HCIST + arranque do módulo de sumarização
Apresentação da conferência em Lisboa. Início do desenvolvimento do módulo de sumarização clínica com LLMs — PTT5, mT5, modelos extrativos e avaliação EN/PT com radiologistas.
FEV – MAI 2026
Avaliação multidimensional + Projeto EI 2025/2026
Framework de avaliação com ROUGE, BERTScore, fidelidade clínica e human judgement por médicos radiologistas. Co-orientação do Projeto EI 51 (servidor HAPI-FHIR) e EI 52 (dashboard médico).
JUNHO – JULHO 2026
Submissão de 3 publicações + escrita da tese
Submissão dos artigos 2 (AI in Medicine) e 3 (MAKE/MDPI). Capítulo de livro para o projeto Blockchain. Escrita da tese de mestrado completa com resultados reais validados.
Pipeline Técnico

Arquitetura do sistema

Uma arquitetura multi-agente em Python que resolve três desafios simultâneos: JSON profundamente aninhado, narrativas clínicas em RTF e validação FHIR em escala.

📦

Projetos de Engenharia Informática

O trabalho de investigação foi integrado em dois projetos de licenciatura co-orientados, permitindo validar o sistema em contexto real de desenvolvimento de software.

Projeto EI · 2024 / 2025
Plataforma Web de Conversão PACS → FHIR
Integração do pipeline de transformação FHIR numa aplicação web completa. Backend Flask com endpoints RESTful para conversão on-demand; frontend para visualização dos bundles FHIR gerados. Persistência em MongoDB. Os alunos integraram diretamente a API desenvolvida no projeto de investigação.
Python / Flask MongoDB FHIR R4 REST API HTML/JS Frontend
Projeto EI · 2025 / 2026
Servidor HAPI-FHIR + Dashboard Médico com Resumo Clínico
Dois projetos complementares: Projeto 51 — servidor HAPI-FHIR R4 configurado e populado com os bundles gerados; Projeto 52 — dashboard web médico com integração do módulo de sumarização clínica, com máquina virtual Ubuntu para deploy. GitHub público com todo o código e documentação.
HAPI-FHIR Dashboard Web LLM Summarization Ubuntu VM .NET / Java
